# Integration Architecture

Generated by BMAD document-project on 2026-06-24.

## Part Boundary

The repository has two runtime parts:

- Backend: Fastify API and Prisma data layer.
- Frontend: Vite React SPA.

The backend owns persistence, authorization, tenant isolation, module enforcement, and production static hosting. The frontend owns navigation, role-specific UI composition, client-side module visibility, and tenant branding.

## Request Flow

```text
Browser
  -> React Router route
  -> apiRequest('/api-relative-path')
  -> Authorization: Bearer JWT
  -> optional X-Tenant-Slug
  -> Fastify tenantPlugin
  -> authPlugin authenticate/authorize
  -> route handler
  -> Prisma tenant-scoped client
  -> PostgreSQL
```

## Tenant Flow

Tenant can be established by:

- Verified custom domain.
- Default tenant subdomain.
- Host-derived tenant slug.
- `X-Tenant-Slug` on local/platform hosts.

The frontend and backend must stay aligned:

- Frontend path-to-module mapping: `frontend/src/data/navigation.ts`.
- Backend request path-to-module mapping: `src/modules/auth/auth.plugin.ts`.
- Backend tenant persistence scoping: `src/lib/prisma.ts`.

## Deployment Flow

The production Docker build:

1. Installs backend dependencies.
2. Installs frontend dependencies.
3. Generates Prisma client.
4. Builds backend TypeScript to `dist`.
5. Builds frontend to `frontend/dist`.
6. Runs `node dist/server.js`.

At runtime, Fastify serves API routes and compiled frontend assets from the same container on port 3333.

## Operational Integration Risks

- If a tenant-owned Prisma model is not in the scoped model set, data isolation can be incomplete.
- If frontend module routing diverges from backend module gating, users can see links they cannot use or reach APIs not represented in navigation.
- If custom domains are enabled without DNS verification, host-based tenant resolution can be misleading.
- If the SPA is not built into `frontend/dist`, non-API routes will not resolve in production mode.
